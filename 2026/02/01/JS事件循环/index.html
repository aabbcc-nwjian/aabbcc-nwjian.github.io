JS事件循环

js的单线程特性

js是单线程的语言，那什么是单线程呢？

进程：一个独立的应用程序，有自己专属的内存空间和资源
线程：线程是进程内的执行单元，是操作系统调度的最小执行单位

单线程简单来说就是在同一时间，只能做同一件事

为什么js是单线程的呢？

  1. 历史原因：

    JavaScript 的诞生时是为 Netscape 浏览器创建，最初的目的是处理简单的网页交互，它的设计理念轻量、简单、易于学习，不需要复杂并发处理

  2. 技术层面：

    内存管理上单线程的设计使得JavaScript 不需要考虑线程间共享内存，简化了内存的管理。

    更重要的一点是，多线程同时操作 DOM 会导致状态混乱，而单线程能避免渲染冲突。想象一下，如果js同时有两个线程，同时对同一个dom进行操作，这时浏览器应该听哪个线程的，如何判断优先级？

同步与异步

同步任务是指程序按照顺序依次执行，每个操作都要等待上一个操作完成后才能进行的任务。

当一个操作在执行时，程序会阻塞，直到该操作完成后才会执行下一个操作。这种执行方式简单直观，但可能会导致程序的响应速度变慢。

异步任务是指程序中不需要等待上一个操作完成就能进行下一个操作的任务。

异步操作通常会通过回调函数、Promise 或者 async/await 等机制来处理。这种执行方式可以提高程序的效率和响应速度，特别适合处理大量的I/O操作或网络请求。

宏任务和微任务

异步任务分为宏任务和微任务

常见的宏任务：script(整体代码)，setTimeout，setInterval，setImmediate，I/O，UI 渲染

1. setTimeout

定时器，用于延迟执行代码

2. setInterval

也是定时器，但会循环执行

3. setImmediate (Node.js 环境)

相当于延迟时间设置为0的setTimeout

4. I/O 操作

是指文件读写、网络请求等操作

5. UI 渲染

常见的微任务：Promise.then/catch/finally，async/await，MutaionObserver

1. Promise.then/catch/finally

Promise本身是同步的，then/catch/finally的回调是异步的微任务

2. async/await

await 后面的代码会被包装成微任务，但await当前执行这一行和之前执行的不变。

3. MutaionObserver

监听 DOM 变化，在变化批量完成后执行回调

4. process.nextTick (Node.js 环境)

在 Node.js 中创建最高优先级的微任务

执行栈与任务队列

执行栈

执行栈是JavaScript引擎用来跟踪函数调用的数据结构，遵循”后进先出”（LIFO）原则。

工作原理：

  1. 当函数被调用时，它会被推入执行栈
  2. 函数执行完毕后，会从栈顶弹出
  3. 栈底通常是全局执行上下文

任务队列

任务队列是用来存放异步任务回调函数的地方。当异步任务完成后，其回调函数会被放入相应的队列中等待执行。

事件循环执行流程

事件循环是JavaScript处理异步任务的核心机制，它持续检查执行栈和任务队列，按照特定顺序执行任务。

  1. 执行同步代码（初始脚本）
  2. 执行栈为空时，检查微任务队列
  3. 执行所有微任务（清空微任务队列）
  4. 执行页面渲染（浏览器环境）
  5. 从宏任务队列中取出一个任务执行
  6. 重复步骤2-5（进入下一轮循环）

因为第一步执行的同步代码也属于宏任务，所以简单来说，一次event-loop是由宏任务开始的也是由宏任务结束的
